# AI Print Studio — презентація

Адреса для гостей: **https://vo1ic.pp.ua/studio**. На головній сторінці також є перехід до готових демонстрацій.

## Текст виступу на 2–3 хвилини

Клієнт надсилає нам зображення спортивної форми — часто це стиснений JPEG, фотографія або презентаційний макет. На ньому вже є кольори, принти, герби й написи. Дизайнеру та конструктору потрібні окремі графічні матеріали, з якими можна продовжити роботу.

Ми створили AI Print Studio — інструмент, який перетворює такий ескіз на чотири прямокутні полотна: перед, спинку, правий і лівий рукав. У кожного полотна є своя основа та окремі шари принтів. З цих заготовок конструктор далі розміщує лекала.

Зараз відкрию збережений проєкт VICTORY. Це результат справжньої попередньої обробки. Під час його відкриття нова генерація не запускається, тому ми можемо одразу показати редактор.

Ліворуч бачимо початковий ескіз, поруч — чотири деталі. Відкриваю передню частину. Кожен принт можна вимкнути, переглянути окремо або згрупувати з іншими. Колір змінюється через палітру виробництва, яку ми прочитали з наданого Illustrator-файлу. Для градієнта зберігається цілісний растровий шар із можливістю змінити його кольорові кінці.

Герби й написи мають окрему бібліотеку. Для якісного джерела можна вирізати вихідні пікселі та поправити маску. Для маленького стисненого знака доступне AI-відтворення у більшій роздільності. Користувач порівнює результат з оригіналом і вирішує, чи приймати його.

Для нового макета вмикаємо профіль презентації: 2K, детальну модель та TIFF у ZIP. Кожна платна операція запускається явним натисканням. Поки вона виконується, сайт показує стан роботи. Демонстраційні проєкти залишаються доступними іншим відвідувачам без генерації.

На виході отримуємо справжній ZIP: оригінальне зображення, фон, прозорі PNG- і TIFF-шари, палітру та manifest із розмірами й координатами. Його можна передати дизайнеру для продовження роботи.

Під час реконструкції AI може змінити геометрію знака або продовжити прихований принт приблизно. Саме тому ми зберігаємо оригінал, даємо ручне редагування та залишаємо остаточну перевірку дизайнеру й конструктору.

Наша мета — скоротити ручну підготовку матеріалів від клієнтського ескізу до набору незалежних графічних файлів. Уже зараз можна відкрити два реальні приклади за цією адресою й самостійно перевірити шари та експорт.

## Послідовність показу

1. Відкрити `/studio` → **VICTORY · птахи**. На екрані має бути синя позначка «Демо» та чотири готові деталі.
2. Відкрити **Перед**. Вимкнути один кольоровий принт кнопкою ока, увімкнути назад. Натиснути назву шару для окремого перегляду, потім «Усі шари разом».
3. Натиснути кольоровий кружечок принта й вибрати зразок із виробничої палітри. Відмітити два шари та натиснути «Згрупувати вибрані».
4. Відкрити **Герби й номери**: показати незалежні PNG герба, RUDYUK та VICTORY.
5. Натиснути **Завантажити ZIP** з увімкненим «TIFF у ZIP». Розпакувати в окрему порожню папку й показати `parts/front/layers/*.tiff`, `elements/*.tiff`, `palette.csv`, `manifest.json`.
6. **Демонстрації** → **ASKELAT · хвилі**. Показати інший стиль принта та незалежні деталі.

## Жива перевірка з гостем

- Перед зміною макета зберегти потрібний проєкт у ZIP: робоча сесія живе в пам’яті вкладки.
- Гість відкриває той самий домен у своєму браузері, натискає «Інший макет» і завантажує JPEG/PNG. Завантаження саме по собі не викликає OpenAI.
- Натиснути **Увімкнути профіль презентації**. Це задає 2K для нових генерацій, Sunburst для деталей та TIFF для експорту. Старі деморезультати залишаються у своїй справжній роздільності 1K.
- Для короткого живого показу: **Герби й номери → Знайти елементи → один потрібний герб → AI-відтворити елемент**. За потреби вписати точний текст/номер або поправити область.
- Порівняти пропозицію з референсом і прийняти її тільки після огляду. За помилки показати справжнє повідомлення, готове демо доступне через «Демонстрації».
- Повний запуск чотирьох деталей потребує до восьми Images-операцій плюс Vision. Він може тривати значно довше короткого виступу. На сцені достатньо одного активного генеративного запуску; інші гості можуть редагувати готові демонстрації.
- Час залежить від OpenAI. Не обіцяти завершення за фіксовану кількість секунд. Не називати більшу роздільність точним відновленням невидимих деталей.

## Підготовка сервера

На поточному комп’ютері порт 8000 проксовано через домен власника. Для запуску на іншій машині потрібні `.env.local`, Node.js 20.9+, Python-залежності та налаштований тунель/проксі. Ключ OpenAI задається тільки на сервері.

```bash
npm ci
python3 -m pip install -r scripts/cv/requirements.txt
npm run build
npm run start -- --port 8000
```

Типові налаштування: `OPENAI_IMAGE_QUALITY=high`, `OPENAI_IMAGE_MODEL=gpt-image-2.5-sunburst`, `OPENAI_ASSET_IMAGE_MODEL=gpt-image-2.5-sunburst`, таймаути Images 240000 мс. Бюджет `OPENAI_DESIGN_REQUESTS_PER_HOUR=40` спільний для деталей і гербів. Він обмежує кількість операцій процесу, а не гарантує грошову суму. Відкриття демо не витрачає цей бюджет.

`/api/jobs` приймає завдання, а браузер перевіряє стан окремими короткими GET-запитами. Це прибирає потребу тримати довге HTTP-з’єднання від браузера до OpenAI через тунель. Черга послідовна, максимум 3 активні/очікуючі завдання; скасоване завдання в черзі не виконується. Бюджет, валідація та помилки основних API збережені.

Ця черга розрахована на постійно працюючий self-hosted Next.js процес. Завдання й результати живуть у пам’яті; перезапуск сервера їх прибирає. Для serverless/кількох процесів потрібні окремий worker, стійка черга/сховище, авторизація й спільний лімітер.

## Що перевірено

- ASKELAT і VICTORY підготовлено з реальних збережених ZIP. SHA-256 архіву та початкові model/usage збережено в `public/demos/*/project.json`. Шари упаковано у lossless WebP, PNG незалежних прийнятих елементів збережено без перекодування. RGB під alpha=0 очищено для зменшення зайвих копій невидимих пікселів.
- Production-браузер без API-ключа пройшов обидва демо, чотири деталі, приховування, групування, зміну кольору, бібліотеку елементів і реальні ZIP із TIFF. За весь сценарій було **0 звернень до `/api/*`**. Є скриншоти desktop/mobile та ZIP у локальному `artifacts/presentation-demos/`.
- Фонова черга окремо перевіряє скасування, обмеження, збереження помилок/Retry-After, відсутність повторного виконання під час polling та захист джерела запиту. Браузерний сценарій реального редактора з явним тестовим upstream перевіряє живий потік через чергу; це тест протоколу, не нова платна генерація.
- Після запуску поточної збірки перевірено локальний порт 8000 і домен `https://vo1ic.pp.ua`: `/studio` та JSON обох демонстрацій повернули HTTP 200, підтверджено новий вміст. Через HTTPS-домен створено навмисно некоректне завдання: POST повернув 202, polling повернув справжню помилку валідації 400, без платних AI-викликів. Звіт — `artifacts/presentation-demos/domain-check.json`. У мережі цієї машини одна Cloudflare IP-адреса не відповідала; перевірка з валідним TLS успішна через іншу адресу `104.21.33.23`. Перед виступом варто перевірити доступ із телефона через мобільний інтернет.

Зміни для завдання №2 публікуються в гілці `feat/task2-presentation-demos`. `origin/main` містить новіші паралельні зміни іншого редактора та 3D-візуалізації; гілку main не перезаписуємо. Поточний локальний сервер на порту 8000 працює зі збіркою цієї Task 2 гілки.
