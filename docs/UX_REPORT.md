# Спрощення сценарію конструктора

## Що заважало

Основний екран одночасно показував технічні параметри, маски, локальне виділення, AI-операції, палітру й експорт. Для чотирьох деталей доводилося вручну вибирати області та окремо приймати кожен із двох етапів. Довгі списки кольорів приховували самі зразки. Високе полотно виходило за видиму область.

## Що змінено

- Прямий вхід `/studio`; завантаження файлу перетягуванням або однією кнопкою. Процедурні демонстраційні макети вилучено з активного входу.
- Один явний запуск: визначення областей → розгортка → поділ на шари для кожної доступної деталі. Обробка послідовна, результат з’являється поступово. Завантаження файлу не викликає API.
- Чотири великі картки деталей; натискання відкриває перегляд шарів. Видимість, окремий перегляд, групування та виробничі кольори доступні без технічної панелі. Градієнт має два редаговані кінці.
- Наявний Canvas-редактор доступний через «Інструменти»: дані, маски, історія й експорт спільні. Полотно вміщується в область, масштаб змінюється окремо.
- Помилка однієї деталі не стирає інші. Повторний запуск пропускає готові й використовує отримані розгортки. Скасування й заміна джерела блокують запізнілі відповіді попереднього запуску.
- ZIP доступний з основного екрана; незбережені маски в будь-якій деталі продовжують блокувати експорт.

## Перевірки

Автоматизований Chromium-сценарій використовує **явно тестовий** OpenAI upstream. Перевірено один запуск усіх деталей, часткову помилку й повтор лише невдалого поділу, шари, групування, перефарбування градієнта, ручну маску, незалежність деталей, ZIP/CRC/розміри/альфу/координати та оригінальні байти. Додатково перевірено невидимі деталі, скасування, заміну файлу під час запиту й відсутність горизонтального прокручування при ширині 390 px.

Окремі тести перевіряють strict schema визначення областей, дублікати/некоректні координати, відсутні деталі, кеш, відсутній ключ, сторонній Origin, rate limits, помилки OpenAI та timeout. Локальний браузерний сценарій маски → відновлення → експорт пройдено з ключем тестового upstream і без ключа.

Збірка й TypeScript проходять. Lint: 0 помилок; 7 попередніх попереджень у неактивних `step-*` і `svg-generators`.

## Живий API

Типовий локатор — **`OPENAI_PARTS_MODEL=gpt-5.4-mini`**, окремо від `OPENAI_VISION_MODEL` для додаткового аналізу логотипів. Прямий структурований Vision-тест на VICTORY завершився за ~12,2 с: відокремлено верхній ряд від презентаційних вставок та визначено анатомічні сторони рукавів. Області тулуба залишаються приблизними й можуть захоплювати сусідні частини. Images Edit на сервері налаштовано на `gpt-image-2.5-sunburst`.

Живий браузерний запуск на `01.jpg` VICTORY завершився без ручних проміжних підтверджень: 4 деталі, відповідно 4/4/2/5 шарів, перед і спинка 1024×1536, рукави 768×1536. ZIP (~52 МБ) пройшов `unzip -t`, оригінальні байти збігаються, розміри PNG та рамки 15 шарів відповідають власним полотнам. 10 принтів мають часткову прозорість; градієнт правого рукава займає повне полотно й закономірно непрозорий. Артефакти: `artifacts/demo-ux/live-victory/` (локальні результати, не production-підстановка).

Цей повний запуск використовував початковий локатор `gpt-4.1-mini`. Візуальна перевірка виявила надто високі області з кількома зображеннями та переплутані рукави, тому його замінено на перевірений окремим запитом `gpt-5.4-mini`. Повторні 8 генерацій після зміни локатора не запускалися. Раніше налаштований `gpt-6.1-terra` повертав timeout від upstream за ~1–2 секунди; збільшення локального deadline цього не виправило.

Ручне уточнення в «Інструментах» залишається потрібним на складних презентаційних аркушах. Автоматичний вибір області й генеративна розгортка не гарантують точного перенесення принта чи збігу стиків. Проєкти потрібно експортувати перед перезавантаженням вкладки.
