# Якість референсів, 2K і справжній TIFF

Оновлення 31.10.2026. Продукт у вебінтерфейсі має назву **AI Promt Studio**.

## Що спричиняло поганий результат

- Приблизні рамки першого Vision-проходу застосовувались як готові координати. На VICTORY це давало тканину замість напису, комір замість монограми та обрізаний тризуб.
- Крупний фрагмент для генерації робився після зменшення всього ескізу. Це втрачало доступні вихідні пікселі маленького знака.
- Необроблений JPEG-обрізок показувався на шахівниці й візуально сприймався як результат. Згенерований результат та референс необхідно розрізняти.
- Типовий вихід 1K обмежував кількість пікселів. Зміна розміру вже готового результату не могла повернути деталі.

## Зміни

1. Пошук знаків і написів: загальний прохід + повторна перевірка збільшених чистих фрагментів і їхніх копій із координатною сіткою. Відповідь проходить strict JSON Schema та Zod, ідентифікатори перевіряються; відсутній/помилковий знак відхиляється, а не підміняється демо. Дублікати зводяться до одного референсу. Для літер повертається прочитаний текст, доступний для ручного виправлення. Кожен реальний Vision-виклик враховується в бюджеті, кеш містить остаточний результат.
2. Vision залишається приблизним. Навколо емблем додається захисне поле, для рядків тексту — менше поле, щоб не обрізати знак при похибці координат. Напис «AI-орієнтир · рамка приблизна» не обіцяє піксельної точності. Рамку можна перемалювати у спільному редакторі.
3. Генерація отримує фрагмент **з оригіналу** та контекст. Менший ескіз цілком не використовується замість вихідних пікселів дрібного знака. Модель отримує назву знака, точний текст за наявності та вимоги до прозорих отворів, без світіння/тканини/сусідніх написів.
4. Типова якість Images — `high`. Нові деталі генеруються нативно 2048×3072, рукави 1536×3072; елементи — 2048×2048 / 2048×3072 / 3072×2048 залежно від пропорцій. 1K залишається економним режимом. Сервер відхиляє неправильні розміри відповіді; прихованого апскейлу готових зображень немає.
5. Необроблений референс має нейтральний фон і напис «ще не згенеровано». Пропозиція на прозорості потребує явного прийняття, лише тоді включається в ZIP.
6. «TIFF у ZIP» типово увімкнено. Поруч із кольоровими PNG/JPEG записуються справжні TIFF (RGB8, unassociated alpha, lossless Adobe Deflate, horizontal predictor, смуги). Оригінальні PNG/JPEG зберігаються. Маски залишаються PNG. Manifest містить відповідність файлів, спільні розміри/координати, DPI=null. Профіль друкарської машини та CMYK не вигадуються.

## Перевірки

Автоматичні тести API використовують явний тестовий upstream офіційного SDK: параметри, два референси, нативні розміри, alpha, кеш, помилки/timeout/rate limit, бюджет кожного виклику. Це перевірки протоколу, **не докази якості AI**.

TIFF незалежно декодовано sharp/libvips і Python Pillow: один/кілька strip, розміри до 2048×2048, точна RGBA-послідовність енкодера, straight alpha, відсутність вигаданого DPI. Браузерний сценарій перевіряє чотири деталі, маски/групи/палітру, прийняття незалежного 2K PNG та справжні TIFF усередині непошкодженого ZIP. Окремий сценарій без ключа перевіряє локальну роботу і справжню помилку AI.

## Межі

Більша кількість пікселів не доводить точне відновлення джерела. Геометрію герба, букви, цифри й кольори потрібно перевіряти дизайнеру. Кращий референс — вихідний вектор/логотип бренду. На великих аркушах Vision може включити сусідній рядок або змістити рамку; залишено ручне уточнення. TIFF зберігає наявний RGB-растр і прозорість, але не створює векторів, фізичного масштабу чи ICC-підготовки до сублімації. Редактор зберігає сесію в пам’яті вкладки, тому перед оновленням сторінки потрібно експортувати проєкт.

## Жива перевірка на клієнтському JPEG

`01.jpg` (VICTORY, 1221×1280) пройдено через production `/studio` та справжній OpenAI, не тестовий upstream. Після першої невдалої локалізації тризуба перевірку змінено: збільшені фрагменти та захисне поле. Остаточний прохід знайшов 5 референсів: повний тризуб, V, RUDYUK, VICTORY, Victory Gymnastics. Слогани презентації не включено. Рамки переглянуто в браузері; RUDYUK ще захоплює частину сусіднього рядка, тому вони чесно позначені як приблизні, а точний текст передається генератору окремо. Артефакти: `artifacts/asset-reconstruction-live/grounded-victory-2k/` (локальні клієнтські дані виключені з Git).

Для тризуба виконано реальну Images Edit генерацію `gpt-image-2.5-sunburst`, high, **2048×2048**. Перша спроба перевищила 120-секундний timeout і показала справжню помилку. Для великих зображень deadline збільшено до 240 с (максимум 300 с), автоматичних платних повторів немає. Повторна явна перевірка повернула повний жовтий знак із прозорими отворами. Його переглянуто на шахівниці, прийнято й експортовано через UI.

Артефакти `artifacts/asset-reconstruction-live/trident-native-2k-final/`: PNG, відповідь із usage, скриншот пропозиції/прийняття, справжній ZIP та `export-check.json`. У ZIP перевірено CRC, точний вихідний JPEG, байт-у-байт незмінений PNG моделі, TIFF 2048×2048 та ідентичну альфу (0..254; модель не повернула alpha=255). 3 288 166 повністю прозорих пікселів. Canvas може округлити RGB частково прозорих пікселів при підготовці TIFF; для alpha≥128 виміряна різниця не перевищила 1 рівня з 255. PNG моделі зберігається без цієї конвертації. Для цього проєкту є 3 TIFF: герб, оригінал і оглядове preview; чотири відсутні деталі чесно позначені missing.

Ця жива перевірка підтверджує новий шлях референс → 2K-герб → прийняття → TIFF/ZIP. Вона **не** є новою живою генерацією всіх чотирьох деталей 2K або всіх логотипів: для деталей великі розміри перевірено API/браузерними тестами з явним тестовим upstream, а попередні живі генерації деталей описані в попередніх звітах. Знак виглядає чисто, але товщина штрихів змінилася відносно малого JPEG — для точного герба потрібен дизайнерський контроль чи векторне джерело.
