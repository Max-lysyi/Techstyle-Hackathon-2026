# Перевірка конструктора: чотири деталі форми

Оновлено 30.10.2026 після узгодження вимог із конструктором.

## Що було принципово неправильно

Попередня версія трактувала чотири прямокутники як чотири шари одного дизайну. Правильна модель — чотири окремі деталі: перед, спинка, правий і лівий рукав. Кожна має власні пропорції, координати, довільну кількість шарів і незалежну історію. Логотипи й текст виключаються; градієнти не розбиваються на кольорові плями.

## Реалізована структура

Огляд показує чотири деталі навіть до генерації. Нестворена розгортка позначена як відсутня. Для кожної деталі зберігаються область у вихідному ескізі, формат, вказівки, чернетка генерації, прийнята розгортка, шари, групи, кольори, маски й Undo/Redo. Перемикання не переносить шари або чернетки масок між деталями. Для рукавів потрібна явна область; сторони анатомічні.

OpenAI Images Edit має два явні етапи: реконструкцію прямокутної площини без написів та карту принтів. Другий етап задає до шести класів графіки плюс основу й службовий клас залишкових написів; створюються лише реально непорожні шари. RGB принтів береться з розгортки, а не з кольорів карти.

Градієнт зберігає всі проміжні відтінки в одному растровому шарі. Суміжні фрагменти карти з’єднуються з градієнтом лише при колірній неперервності їхньої спільної межі. Для ручного виправлення доступне об’єднання обраних принтів у цілісний градієнт. Групування окреме й недеструктивне: воно не склеює пікселі.

Перефарбування градієнта змінює два колірні кінці за збереженою колірною координатою растра й текстурним залишком. Це оцінене редагування растра, не відновлені параметри оригінального векторного градієнта. Палітра — 143 фактичні зразки наданого `кольори форма.ai`, із джерельними CMYK та ICC таблиці; Pantone не вигадується.

## Дефекти, знайдені при візуальній перевірці

- Антиаліасинг між кольорами AI-карти породжував третій колір. Просте зіставлення з найближчим RGB-кодом створювало зайві шари та помилкові маски написів. Декодер тепер поширює впевнені сусідні класи на невпевнені межі. Для службового класу написів використовується суворіша впевненість кольору й мінімальна підтримка: одиничний світлий піксель не запускає вилучення.
- Модель іноді розділяла текстуру та плавний градієнт у межах одного поля. Додано перевірку колірної неперервності та явне ручне об’єднання.
- Прозорі поля навколо AI-відповіді неприйнятні для повної прямокутної заготовки. Сервер перевіряє розмір і непрозорість відповіді, основа експортується повнорозмірною.
- Експорт перевіряє незбережені маски всіх деталей, а не лише активної.

`node scripts/evaluate-garment-parts.cjs` пропускає збережені справжні відповіді через поточне декодування, локальну корекцію та побудову шарів без нових API-витрат. HTML, повнорозмірні PNG, приклади перефарбування та JSON — `artifacts/garment-parts-quality/`. Перевіряється точне складання очищеної робочої композиції; це не оцінка точності розгортання відносно прихованої 3D-поверхні.

## Автоматизовані перевірки

Браузерний production-тест використовує явний тестовий upstream із відомими масками, а локальний OpenCV виконує реально. Це не видається за нову перевірку OpenAI на клієнтських макетах. Перевірено:

- Чотири різні деталі з форматами 1024×1024, 1024×1536, 768×1536 і 1536×1024.
- Різну кількість шарів, єдиний градієнт, відсутність шару логотипів.
- Збереження груп і перефарбування після перемикання деталей.
- Приховування групи, перегляд групи та окремих шарів.
- Ручну корекцію маски, збереження її чернетки при перемиканні та відсутність змін у масці іншої деталі.
- Блокування експорту через незбережену маску неактивної деталі.
- Вилучення навмисно залишеного тестового тексту через OpenCV.
- Точні байти оригіналу, розміри PNG/масок, реальну альфу, повну основу, sourceRect/normalized coordinates, групи й градієнти у manifest, `unzip -t`.
- Відсутність підставлених готових картинок без API-ключа.

Unit/API-тести перевіряють кольорові класи, некоректні карти, неперервність градієнта, відсутність накопичення помилки при перефарбуванні, ручне об’єднання, маски, ізоляцію кешу за деталлю, валідацію, відсутність ключа, API-помилки, rate limit, timeout і бюджет. Збережені перевірки локальної сегментації, реконструкції та ZIP також запускаються.

## Практичні межі

Модель переінтерпретовує й продовжує візерунок; це не точне інверсне UV-розгортання. Масштаб, положення хвилі, стикування деталей і невидимі ділянки потребують перевірки конструктора на лекалах. Семантичні маски можуть потребувати виправлення. На складному фоні локальне вилучення залишкових написів може розмазати текстуру. Поточне редагування градієнта — растрове.

До виробництва потрібні узгоджений майстер, фізичні розміри/припуски, перевірка стиків, профіль конкретного принтера і пробний друк. До публічного сервісу — спільні бюджетні ліміти, автентифікація, черга та тривале збереження/повторне відкриття проєкту. Кеш і ліміти зараз локальні для процесу; при перезапуску скидаються.
