# AI Print Studio — розгортки деталей

Зведений JPEG/PNG ескіз спортивної форми → **чотири незалежні прямокутні заготовки**: перед, спинка, правий і лівий рукав. У кожної деталі своя роздільність, основа та довільна кількість кольорових принтів/орнаментів/текстур. Градієнт зберігається цілісним шаром. Логотипи, герби, написи й номери прибираються з розгорток і опрацьовуються окремо: AI-реконструкція у більшій роздільності або локальне вирізання з оригіналу.

Це заготовки принта для наступного накладання лекал конструктором. Фізичні розміри, лекала й достовірне відновлення невидимих ділянок не заявляються.

## Запуск

Потрібні Node.js 20.9+ та Python 3.10+:

```bash
npm ci
python3 -m venv .venv
.venv/bin/pip install -r scripts/cv/requirements.txt
source .venv/bin/activate
# Виконайте лише якщо .env.local ще не існує:
cp .env.example .env.local
```

У `.env.local` встановіть серверний `OPENAI_API_KEY` і `CV_PYTHON=/абсолютний/шлях/.venv/bin/python`. Ключ не зберігається в браузері, Zustand або localStorage.

```bash
npm run dev -- --port 8000
# або:
npm run build
npm run start -- --port 8000
```

Генерація потребує OpenAI. Локальні маски, палітра й експорт доступні без ключа; платна операція без ключа повертає справжню помилку.

## Простий сценарій і демонстрація

Відкрийте **http://localhost:8000/studio** — прямий вхід до редактора.

На стартовому екрані є **дві готові демонстрації: ASKELAT і VICTORY**. Вони завантажують справжні раніше отримані результати у той самий редактор: чотири деталі, маски, шари та прийняті графічні елементи. Можна змінювати кольори, видимість, групи та експортувати PNG/TIFF без API-ключа й без нового аналізу. Синя позначка «Демо» залишається видимою, походження результатів записується в manifest. Відкрити інший приклад можна кнопкою «Демонстрації» у шапці.

**«Увімкнути профіль презентації»** задає 2K для нових генерацій, детальну модель для деталей і TIFF у ZIP; платний запит ця кнопка не запускає. Готові 1K-демо не збільшуються. Довгі AI-операції працюють через `/api/jobs` і короткі запити стану, що підходить для доступу через домен/тунель. Черга та результати зберігаються в пам’яті одного постійного Next.js процесу.

Текст виступу, послідовність показу та налаштування: [docs/PRESENTATION.md](docs/PRESENTATION.md). Адреса для гостей у поточному середовищі: **https://vo1ic.pp.ua/studio**; перенесення репозиторію на GitHub саме по собі не налаштовує домен на іншій машині.

1. Перетягніть JPEG/PNG або натисніть «Завантажити макет». До 20 МБ / 16,7 Мп; оригінальні байти зберігаються окремо, preview до 1536 px. Завантаження не викликає API.
2. **«Розкласти макет»** знаходить окремі графічні елементи та області чотирьох деталей. Для деталей виконує розгортку без написів і поділ на принти. До 5 Vision-запитів із перевіркою областей + 8 Images Edit. Назви й приблизні рамки першого проходу перевіряються на збільшених чистих фрагментах із координатною сіткою; додається захисне поле навколо знака, адже Vision не дає точних координат; порожня тканина й помилкові підписи відсіюються. Дублікати одного знака об’єднуються за найчіткішим референсом. Відсутні вигляди не вигадуються. Типово використовується нативна генерація 2K із якістю high; перемикач якості задає роздільність **нових** деталей, не збільшує старі результати. Готові деталі повторно не генеруються; отримана розгортка повторно використовується, якщо не вдався лише поділ.
3. Чотири прямокутники показуються поруч. Натискання відкриває шари, видимість, окремий перегляд, групування та виробничі кольори. Градієнт залишається цілісним принтом із двома редагованими кольоровими кінцями.
4. Вкладка **«Герби й номери»** показує референси з ескізу. Якщо потрібні лише елементи, натисніть тут «Знайти елементи», не генеруючи чотири деталі. Презентаційні підписи й заголовки відсіюються; окремі бренд-референси дозволені.
5. Для потрібного елемента задайте точний напис/номер, якщо відомий, та натисніть **«AI-відтворити елемент»**. Або відмітьте до 8 елементів і натисніть «Згенерувати вибрані». Пошук не запускає ці платні операції автоматично. В «Референс і параметри» є уточнення області, напрямки відтворення та формати 2048×2048 / 3072×2048 / 2048×3072 та економні 1K-формати. Модель отримує крупний фрагмент і навколишній контекст. Фрагмент спершу вирізається з повнорозмірного оригіналу, потім готується для моделі: зменшення всього ескізу не викидає деталі маленького логотипа. Крупний референс може бути технічно збільшений для видимості моделі; це не додає оригінальної деталізації.
6. Порівняйте **«Результат / Оригінал»**, перевірте всі літери, цифри, колір і форму. **«Прийняти PNG»** включає AI-варіант в експорт; **«Відхилити»** залишає оригінал і попередній прийнятий варіант. Змінені після генерації параметри блокують прийняття старої пропозиції. Неприйняті варіанти не експортуються. Повтор незміненого запиту використовує кеш; для нового варіанта додайте уточнення.
7. **«Завантажити ZIP»** експортує готові деталі та прийняті елементи. Типово «TIFF у ZIP» увімкнено: поруч із кольоровими PNG/JPEG записуються справжні `.tiff` з тією самою роздільністю, RGB 8 bit, прямою альфою та lossless Adobe Deflate. Маски залишаються PNG. Стиснення виконується у браузері, без зовнішнього сервісу. DPI та ICC-профіль друкарської машини не вигадуються. Окремий PNG доступний на картці після прийняття. «Зупинити» перериває поточний запуск; новий файл скасовує попередню обробку.

Локальне вирізання залишається в розділі «Локальні інструменти» → «Локально без AI». Воно зберігає початкову роздільність і корисне для чітких джерел. Маски, пензлі й історія працюють у тому самому редакторі. Кнопка «Маска локального вирізання» редагує саме вихідну маску, а не згенерований варіант. Ручне редагування альфи згенерованого PNG поки не реалізовано; можна уточнити референс/інструкцію та повторити відтворення.

**«Інструменти»** відкривають детальне редагування: області, формати деталей, окреме прийняття/відхилення розгортки, локальні маски, пензлі, Undo/Redo, порядок/назви/об’єднання шарів, імпорт палітри CSV/AI/PDF. Полотно вміщується у вікно. Локальні інструменти працюють без ключа; платні дії без ключа показують справжню помилку.

Розгортки та відтворені елементи є **генеративною реконструкцією**. Модель може змінити деталі герба чи напису; більша кількість пікселів не доводить відновлення справжніх прихованих деталей. Векторні оригінали бренду бажані, якщо потрібна точність. Фізичні розміри, DPI, готовність до друку й точне 3D-розгортання не заявляються.

Чотири деталі мають незалежні шари, кольори, маски, групи та історію. Проєкт живе в пам’яті вкладки: експортуйте перед перезавантаженням.

## ZIP

`AI_Print_Studio_project.zip` містить точний `original.jpg/png`, кореневі `manifest.json` та оглядовий `preview.png`. У `parts/front`, `parts/back`, `parts/right-sleeve`, `parts/left-sleeve` для кожної готової деталі:

- `master.png` — прийнята й очищена розгортка;
- `background.png` — однотонна основа;
- `preview.png` — поточна композиція видимих шарів і груп;
- `layers/*.png` — справжні растрові шари з альфою;
- `masks/*.png` — маски тієї самої роздільності;
- `palette.csv` — фактична палітра композиції та найближчі фабричні зразки;
- `manifest.json` — розміри, порядок, видимість, групи, кольори, градієнти та джерело області;
- `removed-marks-mask.png`, якщо прибиралися залишкові написи.

Папка `elements/` містить прийняті незалежні PNG і маски. Для локальних елементів розмір PNG відповідає рамці оригіналу. Для AI-елементів — власний растр, типово 2048–3072 px із `bounds: (0,0,width,height)`, `source: ai-reconstruction`, моделлю, usage, текстом/інструкцією та `sourceBounds` відносно ескізу. Вихідний PNG моделі експортується без повторного перекодування. Якщо є локальне вирізання того самого елемента, воно зберігається окремо як `*-original-extraction.png`.

Пропозиції без прийняття не включаються у `elements`; знайдені області окремо описані в `detectedElements`. Елементи не розставляються автоматично на розгортках: достовірне перетворення координат невідоме (`placement: null` для AI). Експорт працює і для самих елементів без готових деталей.

Усі шари **однієї** деталі мають її повний прямокутний розмір і зміщення `(0,0)`. Розміри різних деталей можуть відрізнятися. Частковий експорт дозволений: відсутні деталі мають `status: missing` у manifest; PNG за них не підставляються. Незбережені маски будь-якої деталі блокують експорт до збереження. Окремий шар активної деталі можна завантажити самостійно.

TIFF є справжнім файлом із TIFF-заголовком, описом каналів, стисненими смугами й альфою; відкривання й пікселі перевірено libvips та Pillow. Мапа PNG → TIFF записана в manifest, рамки й зміщення спільні. Немає фіктивних PSD/SVG чи заяви про готовність до промислового друку.

Старі архіви `MAXSport_parts*.zip` можна доповнити TIFF без повторної AI-генерації (потрібен Pillow):

```bash
python3 scripts/add-tiff-to-project.py 'MAXSport_parts(1).zip' AI_Print_Studio_project_with_TIFF.zip
```

Скрипт зберігає PNG/JPEG без змін, додає TIFF і посилання в manifest, перевіряє RGBA та CRC. Початковий архів не змінюється; наявний вихідний файл не перезаписується. У поточному вебредакторі залиште «TIFF у ZIP» увімкненим. Архів із нового експортера має назву `AI_Print_Studio_project.zip`. Якщо вкладка досі завантажує `MAXSport_parts.zip`, вона використовує попередній код: спершу експортуйте поточну сесію, а потім оновіть сторінку.

## Палітра виробництва

`src/data/factory-palette.json` містить 143 фактично прочитані прямокутні зразки з наданого `кольори форма.ai`, вихідні CMYK, SHA-256 та ICC U.S. Web Coated (SWOP) v2. HEX перераховано через ICC таблиці в sRGB. Порівняння — Lab/ΔE76; CMYK кольорів макета залишається приблизним. Профіль таблиці не є профілем сублімаційного принтера. Pantone не вигадується.

Можна імпортувати `name;hex` CSV або PDF-сумісний Illustrator/PDF із простими векторними прямокутними зразками. Універсальний розбір довільного `.ai` із трансформаціями/spot colors/символами не підтримується; використовуйте CSV.

## Активний код і ліміти

Один редактор: `studio-page.tsx` → `editor-view.tsx` → `decomposition-workspace.tsx`. Останній керує чотирма сесіями деталей і спільними інструментами Canvas. Дані й операції шарів — `src/lib/garment-parts.ts`. Старий `four-layer-design.ts` більше не використовується основним сценарієм; `step-*`/`pipeline-store` також не активні.

- `/api/design`: офіційний OpenAI SDK, Images Edit, частина виробу входить у prompt і ключ кешу. Перевірка PNG, розмірів та непрозорого прямокутника. Типово до 40 запитів/год/процес (`OPENAI_DESIGN_REQUESTS_PER_HOUR`, 1–200); 2 запити на деталь, попадання в кеш не рахуються, timeout типово 240 с (`OPENAI_DESIGN_TIMEOUT_MS`, максимум 300 с), без SDK retries. До 12 успішних відповідей кешуються на 30 хв.
- `/api/cv`: локальний Python/OpenCV, фрагменти до 4 Мп, timeout 30 с, максимум 2 паралельні операції. Ключ OpenAI у Python не передається.
- `/api/analyze`: Responses API; автоматичне визначення областей використовує `OPENAI_PARTS_MODEL` (типово `gpt-5.4`), бібліотека оригінальних елементів (`X-Analysis-Task: artwork-elements`) використовує `OPENAI_ASSET_VISION_MODEL` або `OPENAI_PARTS_MODEL`; старий ручний аналіз логотипів — `OPENAI_VISION_MODEL`; режим `X-Analysis-Task: garment-parts` визначає рівно 4 області через strict JSON Schema + Zod, кешує до 8 результатів на 30 хв за вмістом/моделлю. До 30 запитів/год/процес, timeout 90 с (`OPENAI_VISION_TIMEOUT_MS`, максимум 120 с), без повторів. Звичайний режим знаходить логотипи в додаткових інструментах. Vision не є джерелом точного контуру.
- `/api/assets/reconstruct`: Images Edit, два референси (деталь і контекст), справжня прозорість PNG перевіряється на сервері. `OPENAI_ASSET_IMAGE_MODEL` (типово серверна Images-модель), якість типово `high`, deadline `OPENAI_ASSET_TIMEOUT_MS` типово 240 с для 2K / 120 с для 1K, максимум 300 с, без повторів. До 8 результатів кешуються на 30 хв. Бюджет і блокування спільні з `/api/design`: одна генерація елемента витрачає одну операцію. Формат параметрів перевірено за [офіційною документацією Images Edit](https://developers.openai.com/api/reference/resources/images/methods/edit).
- `/api/inpaint`: додаткове відновлення в локальному редакторі; Images Edit композититься лише в дозволеній масці.
- Usage та request ID логуються без ключів і макетів; usage відображається для готової деталі. Фактичні гроші — у кабінеті OpenAI. Кеш і бюджетні ліміти локальні для процесу; публічний сервіс потребує авторизації та спільного лімітера.
